# Сальдо

Мобильное приложение для iOS и Android. Счета, операции, сделки, бюджеты и выплаты хранятся в локальном файле приложения. Flutter 3.47.9, Dart, атомарное сохранение JSON, path_provider, file_picker и csv.

## Запуск

Установите Flutter 3.47.9. Для Android нужны Android SDK и эмулятор или телефон. Для iOS нужны macOS, Xcode, iOS Simulator Runtime и CocoaPods, если Flutter запрашивает его через `flutter doctor`.

Из корня репозитория:

```sh
./scripts/bootstrap-mobile.sh
cd mobile
flutter devices
flutter run
```

При нескольких устройствах добавьте `-d ID_УСТРОЙСТВА`. Платформенные папки генерируются скриптом. Поддерживаются iOS 16+ и Android 10+. Зависимости закреплены в `pubspec.lock`. После установки и сборки основные функции работают без сети.

## Возможности

- Счета и сбережения в RUB, USD и EUR, начальные остатки, долги и ручной курс пересчёта в рубли.
- Расходы, доходы и переводы между счетами. Для перевода между валютами задаётся сумма списания и сумма зачисления. Операции можно удалять.
- Просмотр и поиск операций за выбранный месяц. Балансы, категории и статистика пересчитываются из сохранённых данных.
- Категории и месячные лимиты с индикатором расходования.
- Покупка и продажа бумаг, комиссии, налог, средняя стоимость, реализованный результат и оценка портфеля. Цена задаётся вручную, график показывает цены записанных сделок и текущую оценку.
- CSV-импорт с предпросмотром. Сделки с одинаковыми ID в одном счёте пропускаются при полном совпадении. Конфликт данных отклоняет импорт целиком. Продажа сверх имеющейся позиции отклоняется.
- Календарь купонов и дивидендов. Даты, общая сумма и налог задаются вручную. Отметка «Получено» зачисляет сумму после налога ровно один раз. Снятие отметки отменяет зачисление.
- Все изменения сохраняются на устройстве и восстанавливаются при следующем запуске. Денежные суммы хранятся целыми копейками, количество бумаг — с точностью до шести знаков.

## Демонстрация

1. На первом экране нажмите «Посмотреть на примере». Получите связанные счета, операции, позиции и запланированный купон. Для собственных данных выберите «Добавить первый счёт».
2. В «Операциях» добавьте расход. Проверьте изменение баланса и статистики. Закройте приложение и запустите снова.
3. Во вкладке «Счета» добавьте второй счёт, затем выполните перевод из формы операции.
4. В «Категориях» нажмите на карточку и задайте месячный лимит.
5. В «Портфеле» откройте актив, измените цену и запишите частичную продажу.
6. Откройте «Календарь выплат», добавьте выплату и отметьте её получение. Проверьте брокерский остаток.
7. В «Портфеле» нажмите значок импорта, выберите «Проверить на образце» и подтвердите. Повторный импорт не удваивает позиции.

## CSV

CSV — UTF-8, разделитель запятая, десятичная точка, дата ГГГГ-ММ-ДД. Столбцы:

```csv
trade_id,date,symbol,name,side,quantity,price,fee,tax,kind
deal-1,2026-11-01,SBER,Сбербанк,buy,10,302.40,3.02,0,Акции
```

`side` принимает `buy` или `sell`. `kind` — «Акции», «Облигации» или «Фонды». `price`, `fee` и `tax` указываются в валюте выбранного брокерского счёта. Размер файла ограничен 1 МиБ. Старый демо-файл с двумя столбцами `trade_id,amount` не содержит данных для расчёта позиций. Используйте новый образец в приложении.

Форматы выгрузок конкретных брокеров ещё предстоит согласовать по реальным файлам. В автономной версии цены, курсы и выплаты вводятся пользователем. Учёт налога использует введённую сумму, автоматический налоговый расчёт не реализован. Процент результата — отношение результата после введённых расходов и выплат к сумме покупок с расходами, без годового пересчёта.

## Данные

JSON хранится в Documents приложения, запись выполняется через временный файл с атомарной заменой. При ошибке записи изменения в памяти откатываются. При ошибке чтения существующий файл сохраняется, приложение показывает ошибку. Удаление приложения удаляет его локальные данные. Локальные данные текущей версии создаются отдельно от прежнего серверного демо. Сведения из старой PostgreSQL автоматически не переносятся.
